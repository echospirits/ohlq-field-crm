# Field workspace and account navigation

Preserve Neat's existing visual identity. Compose shared controls around the next useful action, with less introductory chrome and fewer empty summaries.

- Desktop sidebar: frequent work and accounts stay visible; Intelligence, Insights & setup, and Administration use one disclosure style. Keep entitlement and role filtering, selected destinations, and administration groups.
- Account sections: Overview, account-specific sales/placements/purchases, Intelligence, Activity, and Details share named tabs. Only available sections exist. Arrow keys, Home and End move between tabs; URL fragments and browser history restore the section. Panels stay mounted so changing sections preserves entered values. Notes and Contacts precede Outstanding work in Overview. Briefing follows that work.
- Contextual actions: account pages own their reachable mobile Log Visit and Directions actions. More actions retains follow-up, targeting, order and edit controls where authorized. Generic Log visit is available in the sidebar and mobile More; a global floating button must not cover page content. Canonical context includes account, source and return destination.
- Briefing: omit unavailable fact rows, show one concise no-history state, and lead with the next action. Keep scores, reasons and missing-input explanations in Relationship evidence. Do not substitute a zero score for missing evidence.
- Worklist: account identity precedes task title; show relative overdue age with the exact date and explicit ownership. Search remains live. Advanced filters have associated labels. Secondary task evidence remains inside the task's editing disclosure.
- Schedule: an empty day should not render a large empty time grid. Personal overdue/undated work retains its 30-day window. A separately labeled, tenant-scoped unassigned summary does not count as the signed-in person's work.
- Section browsing: use text hierarchy and thin dividing lines for Schedule, evidence, imports, settings and other optional disclosures. Avoid large white collapsed cards. Keep a generous invisible touch target around compact visible text.
- Visits: compact known account context, notes before optional outcomes/contact/status detail, and persistent Save/Cancel. Preserve existing manual-interaction semantics, task resolution and source context.

Use theme tokens in light and dark modes, visible focus, 44px frequent touch targets, contained section-tab overflow, and explicit loading/empty/error/disabled/success feedback. These patterns do not authorize changes to data models, permissions, scoring, provider behavior, or release boundaries.
