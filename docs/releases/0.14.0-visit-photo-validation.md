# Visit photo viewer — 0.14.0 TST validation

Validated on 2026-10-02 for `0.14.0-dev`.

## Cause and change

The visit-history `.content-section` uses `content-visibility: auto`, which establishes containment for its descendants. The old fixed-position photo overlay was rendered within that section, so desktop centering followed the long list instead of the viewport. Mobile scrolling could move the containing region and clip the photo.

The shared `VisitPhotoGallery` now portals a native `dialog` to `document.body` and opens it with `showModal()`. The browser's top layer keeps it above page navigation and outside visit-list containment. Dynamic viewport sizing centers and bounds the photo panel. A fixed body locks background scrolling, retaining the original scroll coordinates and inline styles for restoration. The existing `useDialogFocus` hook handles keyboard focus and Escape; closing restores thumbnail focus without scrolling.

The responsive checks use the real component in a local synthetic history fixture, not a live customer visit. Physical iPhone Safari scrolling was not tested. The scroll lock includes the fixed-body strategy for iOS Safari, but device confirmation remains a useful release smoke check.

No migration, environment change, photo-storage change, or data backfill. Delivery is only to `staging/tst` in `echospirits/neat-tst`; production/main promotion remains a separate task.
