### Model selection correction

The initial independent-horizon audit found two decreasing cumulative paths: product 2802B at 6.05 / 11.05 / 6.08 cases and 2828B at 1.35 / 3.37 / 1.65 cases for 30/60/90 days. That architecture was rejected before delivery. Model v1.3 selects one method from pooled horizon-specific daily MAE and uses a shared nonnegative 90-day path. Each horizon retains its own error, confidence, range, prior-year comparison and evaluated actuals. No point-estimate clamping is used. An explicit computation context shares source maps, trajectories and historical checks without global caches.

The historical audit uses nested model selection at old cutoffs, comparing the selected pipeline with weighted-mean and seasonal-naive baselines on common available windows. Its results are exploratory evidence from the current retained portfolio/history, not a guarantee of future accuracy. The first architecture's ignored audit JSON is retained as investigation evidence, not release validation.

Final read-only audit: `scripts/audit-production-forecasts.ts --environment=test --env-file=<verified-tst-env> --organization=org_echo_spirits --as-of=2026-11-01 --holdout-folds=3 --output=output/forecast-audit-coherent-20261103.json`. Model v1.3 completed in 121.7 seconds with 119 cached product/origin bundles, 153 outer product windows and 2,448 inner selected-method location folds. All outer actuals were available, windows were nonoverlapping within each horizon, and inner horizons ended by each selection cutoff. All 17 products were forecastable/Low at all horizons. No location or product cumulative reversal remained. Output stayed local and ignored; no database writes occurred. Production and invalid-output CLI guards were also verified to reject before database reads.

| Horizon | Pipeline WAPE | Weighted-mean baseline | Seasonal-naive baseline |
| --- | --- | --- | --- |
| 30 days | 61.7% | 76.1% | 74.6% |
| 60 days | 70.8% | 73.0% | 81.9% |
| 90 days | 89.4% | 92.1% | 76.8% |

WAPE divides absolute error by actual demand; these values are not confidence probabilities. The seasonal baseline outperformed the selected pipeline at 90 days in this small sample. No accuracy or calibration guarantee is claimed. Three windows per product are useful diagnostic evidence, not grounds for relaxing confidence thresholds.

### Initial confidence diagnosis

Read-only TST inspection on November 3: latest saved v1.1 run generated November 2 at 22:38 UTC, through November 1. All 17 eligible product snapshots were Low. All 102 location series had 1,096 covered days and eight historical evaluations; insufficient elapsed history was not the cause. Each product included a zero-only direct location, `DIRECT:50114`, with undefined WAPE/volatility, forcing Low under the weakest-location aggregation rule. Other direct series also had sparse demand, high historical errors or volatility; some warehouse series were already Medium. This is a diagnosis of the inspected TST run, not proof that every production run has the same state.

Confidence thresholds are unchanged. More observations can improve coverage/error/stability, but passing time does not resolve undefined zero-demand metrics or guarantee better accuracy. Candidate-selection folds support method comparison; they are not an independent untouched holdout evaluation. Native source posting availability is inferred from invoice/shipment chronology, not reconstructed report receipt timestamps. During the initial TST-only investigation, no production saved-run query was performed because a safely labeled production identity had not yet been established. The subsequent release independently verified production identity before any production reads or activation, as recorded above and below.

November 3 follow-up: the owner authorized excluding the one historical invoice that originated `DIRECT:50114`. Model v1.4 now omits its 17 proven derived planning series through an auditable input policy, preserving original records and old forecasts. Current TST planning has 85 series, and all products remain Low for other active-demand reasons. See [the exact exclusion receipts](production-invoice-exclusion-validation.md); the initial diagnosis above describes the earlier saved run.
