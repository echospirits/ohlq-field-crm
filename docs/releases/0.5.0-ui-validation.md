# Neat 0.5.0 interface and browsing acceptance

## Scope and method

The owner approved the field-workspace mockups, expanded the work to an application-wide UI/UX and performance review, explicitly authorized main promotion, and on October 29 requested text hierarchy and dividers instead of oversized white navigation boxes. The 0.4.1 performance and 0.4.2 source-download fixes are preserved. No migration, dependency upgrade, provider activation, hosted configuration change or live CRM write is part of this release.

The initial review inventoried route entrypoints and sampled Schedule, Worklist, retail/restaurant directories and details, visits, Pipeline, orders, search, intelligence, analytics, Forecast, profile, calendar, tags, users and administration. Existing authenticated TST access was used; no shared temporary admin session was created. This review is a practical acceptance sample, not an exhaustive WCAG certification or measurement of every role/data combination.

## Findings and corrections

| Priority | Finding | Result |
| --- | --- | --- |
| P1 | Account detail buried relevant work in unrelated native disclosures | Named tabs preserve deep links, history and entered form values; Overview leads with Notes, Contacts, Worklist and concise briefing. |
| P1 | Missing history repeated across a wide briefing | Only known facts display. One empty state and next action lead; uncertainty, scoring and provenance remain in Relationship evidence. |
| P1 | Directory and intelligence browsing rendered excessive records | Retail/ordinary restaurant directories use stable server pages of 50; retail intelligence uses 25 instead of 250; restaurant opportunities use 25 instead of 50. Counts, continuation and filter/order semantics remain available. |
| P1 | Global visit button covered data and search | Sidebar/mobile More provide generic Log visit; contextual account actions remain close to the account. |
| P2 | Schedule and common submenus appeared as oversized white boxes | Shared optional sections use transparent rows, title hierarchy, one chevron and dividers. Form/overlay surfaces remain distinct. |
| P2 | Repeated unknown metadata and low-value controls obscured decisions | Known directory facts lead; evidence, scope filters, targeting and pursuit preferences are progressively disclosed. |
| P2 | Legacy mobile controls were 34px high | Shared 44px floor for buttons/disclosures; mobile More has a visible Log visit entry and Escape support. |
| P2 | Narrow-desktop intelligence columns could exceed available space | Retail's three-column layout begins at 1100px; smaller layouts stack. |

The Forecast warning was investigated rather than suppressed: its query already selects the newest attempt for each market/source, so failed/incomplete-source warnings remain truthful. Sources and Import anchors now reveal their respective disclosure.

## Performance and limits

Normal directory pages now fetch/render 50 rows instead of rendering 250 retail/300 restaurant rows and retrieving the entire restaurant set. Explicit computed-rank sorts retain their bounded complete-sort path so pagination cannot falsify rankings. Intelligence page sizes reduce rendered markup; the scoring models are unchanged. Layout/page authentication shares an in-flight read only within the same request/cookie, with new requests revalidating access. These are verified reductions in query/render work; no unmeasured production latency percentage or Core Web Vitals improvement is claimed.
