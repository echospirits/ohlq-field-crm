# Neat 0.15.4 — Automatic restaurant research recovery

## Fixed

- Scheduled restaurant research uses Echo Spirits’ configured account states on every worker step. The pilot can settle only after its saved jobs are visible and accounted for.
- A pending OpenAI response can occupy one slot while other jobs proceed. Responses still pending beyond the polling deadline or no longer available from the provider retain their original response ID and require reconciliation before the account can be submitted again.
- Each scheduled run works through a single pilot, including an existing pilot resumed after interruption.

## Production recovery

The October 4 automatic pilot has 500 original jobs. Of these, 225 were never submitted and one has an existing provider response ID. Recovery uses the same pilot and job rows, refreshes city values on the six affected unsent jobs, and fetches the existing response before deciding its outcome. An inaccessible response remains recorded for reconciliation. Verify the exact pilot counts and original response identity before reopening it, then reconcile the saved job statuses and submission counts after the run.

This hotfix is based on production `37c70f6c8658b04e6da4e7d336554cba242c8fbb`. It uses the existing schedule, tenant entitlements, application reservations, and database schema.
