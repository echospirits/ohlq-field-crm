# 0.13.3

Release date: 2026-10-01. Production version: `0.13.3`.

## Fixed

- OHLQ data loads can resume the wholesale report after signing in again, preventing a false login timeout when OHLQ redirects straight to Power BI.

## Internal release information

- Production base: `da3ba033654822ca8dca1ce4f23228d16a4dddea` (`0.13.2`). Only the report login handoff, regression tests, version metadata, and release documentation are included. Current TST base: `7d09c8efceca37dce1f3f72c03c15cd8db244e5e`; unrelated 0.14 development work is excluded.
- Root cause: `waitForOhlqPartnerLogin` only accepted `/partner`. In production run [36858853786](https://github.com/echospirits/ohlq-field-crm/actions/runs/36858853786), re-login navigated to the requested wholesale report but the partner-page wait timed out after 60 seconds. TST run [36601292112](https://github.com/echospirits/neat-tst/actions/runs/36601292112) shows the same failure.
- The fix accepts only the expected report on the HTTPS Power BI host, or the Microsoft sign-in handoff, when report context is supplied. Master login behavior, rejected-credential detection, password-reset detection/redaction, tenant credentials, report-frame validation, and import validation remain in force. Successful re-login continues the report immediately, including on the final retry.
- Other observed incidents: production [36711946924](https://github.com/echospirits/ohlq-field-crm/actions/runs/36711946924) failed in Brand Master product discovery with a transient database connection failure; subsequent runs succeeded. Production [36418988974](https://github.com/echospirits/ohlq-field-crm/actions/runs/36418988974) stopped at the Account Master identity-conflict safeguard; later master runs succeeded. TST [36330542552](https://github.com/echospirits/neat-tst/actions/runs/36330542552) failed clean installation on a stale lockfile; current clean installation succeeds.
- Read-only production database audit on October 1 confirmed retail/wholesale rows for September 25–30: 125805/26949, 109882/6129, 60168/548, 74661/13167, 81690/17924, and 86377/20050 respectively. The failed September 29 refresh marked its import status errored with zero status row count, but retained its previously imported rows and `lastSuccessfulAt`. Status alone must not be interpreted as missing data.
- No migration, database repair, credential change, environment change, or feature entitlement change. Duplicate-trigger suppression is outside this narrow hotfix; the cron currently dispatches separate dates and GitHub schedules can also trigger imports. Skipped seasonal slots are not successful data loads.
- Validation: 529 tests passed (including eight new login/handoff cases), typecheck passed, optimized build passed against the final source. The first sandboxed build failed because the workflow compiler could not read parent directories; the identical authorized build succeeded. The read-only release audit and actual main/TST differences were reviewed.
- Tenant data access and user-facing layout are unchanged; tenant isolation is covered by existing regression tests. Mobile/desktop interface smoke checks are not applicable to this browser-import-only change.
- TST validation: 557 tests, typecheck and optimized build passed against the same report source; TST keeps version `0.14.0-dev`.
- Deployment, candidate commit, stable tag, and post-deployment health evidence will be recorded after publication. A patched live OHLQ run has not yet been verified.
