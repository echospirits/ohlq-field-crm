# 0.9.0 automatic forecasting refresh release

The owner requested an automatic refresh button instead of the normal manual source-upload section, with delivery to both TST and main explicitly authorized. This stable 0.9.0 production candidate is prepared selectively from main `844cbf9539ff681b9857242248ef0d9762c604b1`. TST development starts from `a9706f50af4f093c530e9ecc7f5735a891124b23`. The prior released application/tag remains v0.8.0 / `3a21899c523c52c226b8ee3d905abbbe057504d5` until production promotion is verified.

## Resulting behavior

Admins and platform administrators in the active entitled Echo context can request a forecasting refresh without choosing files, entering coverage dates or leaving the current search/horizon. Sales remains read-only. The dedicated forecast-only workflow downloads the existing complete case-history and DC guidance reports, saves forecasts and fills missing daily operational observations using existing authorized connections.

Successful existing daily operational snapshots remain immutable and retain their actual observation dates. A successful background request does not establish that every operational provider was observed again. Stored request status distinguishes waiting, running, success, partial failure, failure and timeout; duplicate clicks reuse the active tenant request, and worker leases fence late completion.

## Selective scope

- New refresh UI, server actions, request/dispatch services, runner CLI and dedicated workflow.
- Optional progress/outcome hooks in the canonical forecasting-source workflow; existing callers keep their behavior.
- One additive request-history table with tenant-scoped requester ownership. Main adds only the compatible User organization/id identity index needed by this relationship; no tasting schema or migration is included.
- Focused behavioral/security coverage and release/operator support. Main's package scripts, test runner/setup, TypeScript configuration and dependency graph remain intact; version metadata advances to stable 0.9.0.

Annual sales, shared inventory, unrelated product policy, provider accounts, credentials, feature entitlements and unrelated TST work are excluded. Historical release records and tags are preserved.
