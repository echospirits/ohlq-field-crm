# Production Supplies — original TST development plan

Historical scope record. The owner subsequently accepted the simplified dashboard and authorized production release on November 12, 2026. The current selective release is documented in [0.10.0 release notes](0.10.0.md), [checklist](0.10.0-checklist.md) and [production validation](0.10.0-validation.md). Earlier TST-only authorization below describes that development phase, not the later code promotion or production provider activation.

**November 12 owner revision:** the current product is a simple Dx5-driven supply status dashboard, with one card per material/location/cycle and only Dismiss. Repeated usage alerts update the same cycle; completed relevant delivery hides it. Neat shows ordering and delivery, while Dx5/Ollie own inventory planning. Tabs/history/manual entry/catalog/record editors are removed from the user flow, with retained data/evidence preserved. Future order/tracking processing is limited to watched materials. This supersedes the broader original workspace scope below; TST-only delivery and all provider/payment boundaries remain.

Scope authorized November 11, 2026: one shared supply coordination workspace with production team mailbox ingestion, evidence reconciliation, line-level classification, needs/replenishment/receipts, live-capable tracking and configuration. Development starts from current `neat-tst/tst` `0d9a17dd` / 0.9.2. The original local checkout and unrelated dirty documentation are preserved in place; implementation is in the isolated `codex/production-supplies` worktree.

Deliver to TST after affected tests, one completed full suite, strict typecheck, optimized build, additive-migration rehearsal, tenant/access tests and phone/desktop browser acceptance. Provider mocks/fixtures and live acceptance must be distinguished. Production promotion and a stable release candidate are separate, unauthorized tasks. Preserve all historical refs and existing TST-only pilots.

Activation uses the default-disabled tenant feature. The Echo setup resolves existing named users without fabricating accounts or addresses; membership, operational grants and mailbox consent remain distinct. The known raisins/Spiced Rum association is tenant setup only and supplies neither a SKU nor a purchase allocation.

No outbound messages, automatic purchasing, inventory transactions, accounting writes, destructive migration, paid subscription or unapproved tracking registration. Recovery hides the feature and stops its jobs by disabling the entitlement or server-side ingestion/tracking switches, retaining operational evidence.
