Status: **released and archived**. Published stable [v0.11.0](https://github.com/echospirits/ohlq-field-crm/releases/tag/v0.11.0) is verified Latest at READY/healthy application `2f36074420a74de75fe1f3e98e48903bc7cd4919`, selectively advanced from production base `f71a71c7f162832bf05afa842b282e947f4dea18` (0.10.2). See [validation](0.11.0-validation.md), [checklist](0.11.0-checklist.md) and the [operator guide](../engineering/bailment-reporting.md).

## New

- The existing native Bailment PO and Invoice download now supplies a typed production Neon reporting snapshot, connected to the original Looker Studio report.
- Sales Stats now shows week-to-date Bailment including today and the previous complete week, both using Monday–Sunday weeks.
- Core Revenue and Sales Stats show actual Bailment source-acquisition time in Eastern time. Saved-viewer reload, global refresh, displayed values and desktop layouts are verified.

## Improved

- Financial reporting retains the complete native invoice-line source independently of forecasting normalization, exclusions and failures. The shared Neon brand-exclusion filter is explicitly attached to every Bailment chart, preserving existing business exclusions and financial-date meanings; unrelated monthly filters remain unchanged.
- Atomic publication, source provenance, replay protection and bounded retention preserve the last complete snapshot during an unsuccessful refresh.

## Fixed

- The daily load's final persisted-data check also verifies the required reporting snapshot, so successful forecasting cannot conceal a failed financial publication.
