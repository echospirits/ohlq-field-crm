# Production Forecasting pilot

Organization-scoped demand planning at **Analytics → Production Forecasting**. A compact **Next 30 / 60 / 90 days** selector updates total expected cases per configured product in the same view. Horizons are cumulative from the same start date; 30 days remains the default. Product links, live filters, selected organization and back links retain the horizon. This is not net production after finished inventory.

## Engine and validation

`lib/productionForecasting/model.ts` defines generic Market × Product × FulfillmentLocation demand/guidance interfaces. Ohio-specific mapping stays in `ohio.ts`; another adapter can supply these interfaces later. No other-state importer or Ohio-only statistical branch is added.

Candidates: 90-day recent mean, weighted 30/60/90-day mean (50/30/20%), simple exponential smoothing, seasonal naive, damped/capped growth plus seasonal shape, and Croston SBA for intermittent series. Forecast daily for the selected horizon. The 30-day detail retains weeks 1–4 plus two remaining days; longer horizons show two or three 30-day segments within the existing space. Growth ratios are capped at 0.65–1.5 and damped; the seasonal model also blends recent demand and longer trend.

Evaluate up to eight non-overlapping rolling origins separately for each 30/60/90-day horizon. Both movement date and source `available_on` must be known at each origin; no future postings enter fitting. Compare candidates on common origins (at least three per horizon), pooling mean absolute error per day with equal weight for each horizon and stable method-order tie-breaking. One model per location produces a nonnegative 90-day path; cumulative totals use its first 30/60/90 days. Historical checks also predict the same full path before scoring each prefix, keeping validation consistent with live behavior. Report WAPE, horizon-adjusted daily-naive-scaled MASE and signed bias; all-zero denominators remain unavailable. Native-source availability is inferred from invoice/ship chronology, not a reconstructed historical report-receipt timestamp. Late corrections are not silently rewritten into history.

High confidence requires 365 consecutive covered days, six backtests, WAPE ≤20%, moderate/low weekly volatility and stable forecasts. Medium requires 90 days, three backtests, WAPE ≤50% and bounded volatility. Otherwise Low. Missing coverage, less than 14 consecutive covered days, or source more than seven days old withholds a location forecast. Any unavailable known location withholds the product total.

Confidence is an evidence rating, not a probability. Product confidence is the lowest location rating. A covered location with all-zero actuals has undefined WAPE and volatility; it remains conservatively Low even with years of history and zero point error. More time alone does not fix this condition. Current source coverage is required for Medium/High. Location disclosures show exact Low blockers and selected-method historical predictions versus actuals. Confidence thresholds are unchanged by this extension.

Location planning ranges use the empirical 80th percentile of absolute error for the selected horizon when at least three errors exist. Sparse history uses an explicitly uncalibrated planning band. Summed product ranges are conservative envelopes, not calibrated probability intervals. They must not be described as guaranteed coverage.

### Read-only historical audit

Run `npx tsx scripts/audit-production-forecasts.ts --environment=test --env-file=<verified-tst-env> --organization=<id> --as-of=YYYY-MM-DD --holdout-folds=3 --output=output/forecast-audit.json`. The date must be completed; omit it to use yesterday in the organization timezone. The named environment must independently identify test/neon-neat-tst and its matching expected database host. Source reads run in a PostgreSQL read-only transaction; forecasts are computed in memory and never saved. Output must be a new JSON file inside this worktree's `output/` directory. No source invoices or credentials are printed.

The report includes location evidence and candidate-selection scores, plus nested rolling historical holdouts: at each outer cutoff, the complete model-selection process uses only earlier observations and inner backtests, then compares the selected forecast with later actual demand. Weighted-mean and seasonal-naive baselines are compared on common product/origin windows. Default three outer windows per horizon; bounded option 1–8. WAPE is absolute error divided by actual demand; bias is positive for overforecasting.

Candidate-selection errors reuse the folds used to choose the method and are not an untouched accuracy test. Outer holdouts improve that evaluation, but remain reconstructions from the current configured portfolio, bounded retained observations and source availability rules. They cannot recover historical report receipt or portfolio decisions that were never recorded. Actual evaluations of immutable saved runs provide a complementary prospective check once each horizon finishes.

Targets are `ceil(forecast × (1 + safety[confidence]))`: defaults High 5%, Medium 10%, Low 15%. Operators can configure `Organization.settings.productionForecasting.safety` with fractions from 0–0.30. No inventory is subtracted. DC guidance never enters the demand equation. Central thresholds suppress small forecast/guidance changes and unusual-demand noise. No production-risk alert is fabricated without a trustworthy independent planning target.

Methods follow rolling-origin evaluation and scaled-error principles in [Forecasting: Principles and Practice](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation).

## Persistence, refresh and access

Migration: `20261028010000_production_forecasting`. Five additive tables hold source imports, demand observations, guidance observations, runs and product snapshots. Composite tenant/source/product foreign keys, date/quantity checks and tenant/product/date indexes protect persistence. Snapshots retain method/version/configuration, per-location evidence, input signals and historical summaries. Finished horizons receive actuals only with complete coverage; old predictions never change. Model v1.3 adds coherent 60/90-day detail and lightweight summaries to the existing JSON while preserving the 30-day root/scalar columns. Longer-horizon evaluated actuals live beside the summary as metadata. No new migration is required. Old runs have no fabricated 60/90-day result and show awaiting refresh until a new run is created. Per-computation caches share known data, trajectories and historical checks across horizons; no results are cached globally between refreshes.

`PRODUCTION_FORECASTING` is a separate optional pilot, disabled in standard packages and TST's broad override. The migration explicitly enrolls `org_echo_spirits` by ID and disables it for other current tenants, preserving explicit choices on replay. Platform plan editing has a separate pilot checkbox. Pages/actions and underlying services enforce the entitlement and organization scope. Existing platform support view supplies its explicit organization context.

Platform administrators can open Production Forecasting directly from desktop navigation, mobile More, Analytics or Platform administration even when their current organization is not enrolled. The forecast page prefers their current/support organization when eligible, otherwise opens an active enrolled organization (currently Echo). Its organization is explicitly labeled; multiple enrolled organizations use the shared searchable picker. This feature-specific view does not change the global Support View cookie or enable the pilot for another tenant. Product/detail/back links and source forms retain the selected organization. Source actions require an explicit platform target and recheck role/enrollment; ordinary users/admins retain their own organization entitlement and cannot forge a cross-tenant target.

Current planning rows omit Distillery Only / A-3a Dist and delisted Ohio products (Brand Master status `30`) entirely. The shared server-side portfolio filter runs before dashboard summaries, counts, totals, search options, detail/history reads and future forecast runs. Active A-3a Bailment remains included. Missing catalog status alone is not treated as delisted, and Ohio status rules do not affect another market. Organization inactive/discontinued/excluded decisions remain enforced. Old imports, observations and saved forecasts remain retained; becoming ineligible hides an already saved row immediately, without needing a new import or forecast refresh.

Successful imports refresh immediately; failure to refresh does not misreport a committed import as failed. A daily 12:30 UTC Vercel cron dispatches the existing Workflow system when the existing cron side-effect gate permits it. TST currently has that gate disabled; this feature does not turn on unrelated jobs. Repeated same-day identical inputs reuse a run; source/config/portfolio changes create another immutable run. A tenant failure does not stop subsequent tenants.

Dashboard reads only precomputed summary JSON and current configured product identities. Drill-down alone reads bounded historical/detail JSON. Models run on the server with at most 1,096 days of observations; source queries are batched, with no per-product history queries. This is demand forecasting only: no ERP, BOM, schedules, allocation automation, purchase orders or AI model.

## Operations / limitations

Use `npx tsx scripts/production-forecasting.ts --env-file=<verified-tst-env> --apply-migration` to apply/register only this reviewed migration. The command verifies target identity and checksum; it does not replay historical migrations. `--organization=<id> --refresh` refreshes an enrolled tenant. Production targets are rejected by this command.

Historical range and direct-invoice policy are configured for automated runs. Live download availability must be checked independently: the signed-in Power BI report returned an upstream render error during development. Do not describe wiring/tests or a skipped Actions run as a successful live download. Inactive/discontinued/excluded products stay outside current planning; historical snapshots remain retained.
